Overview

Goal of the review

Many small cloud environments slowly become expensive and insecure over time: test machines are never shut down, old snapshots stay forever, and security groups remain open “just for testing”.

This project focused on building a simple review process that looks at both cost and security side‑by‑side and suggests actions that save money without weakening the security posture.

Inventory of running resources Identify idle / oversized instances Check basic security group rules Review storage encryption & backups Summarize cost vs risk
Process

How the cloud environment was reviewed

High‑level process:

The review went through resources service‑by‑service, noted which ones were needed, how much they cost, and whether they were configured securely. Each finding had a recommended action: keep, right‑size, shut down, or secure.

Step‑by‑step review
1. Cost & usage overview Looked at monthly cost breakdown by service to see where most money was going and identified unusual spikes or rarely used services.
2. Compute resources Listed all VMs / instances, checked CPU / memory usage over time, tagged them (prod / test), and marked idle / oversized ones for action.
3. Storage & snapshots Found unattached volumes, very old snapshots and buckets with high storage usage, and noted which ones could be cleaned up or moved to cheaper tiers.
4. Security groups & public access Reviewed inbound rules for overly open ports (0.0.0.0/0 on SSH/RDP/DB) and flagged them for tightening or removing.
5. Encryption & IAM basics Checked which storage resources were unencrypted and looked for IAM users with overly broad permissions that could be simplified.
6. Action plan Grouped findings into quick wins (delete, stop, resize) and medium tasks (policy updates, enabling encryption, improving backups).

Learnings

What this project taught me

Key takeaways
  • Cost optimization and security are connected: unused resources are both wasteful and risky.
  • Simple reports (tables + tags) are enough to find good “first round” savings.
  • Having a repeatable checklist makes reviews faster and easier to automate later.
  • Small changes (stopping idle dev, tightening SGs) can reduce cost without redesigning everything.
Next steps
  • Automate checks with scripts or policies (for example, flag untagged or idle resources).
  • Add a cost & security dashboard that updates automatically each day.
  • Integrate this review into regular release / sprint cycles as a habit.
