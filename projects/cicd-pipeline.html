Overview

Why this pipeline exists

The main objective of this project was to remove manual steps from deploying a web application. Every code change should go through a predictable pipeline that runs tests, builds an artifact, and updates the running environment without logging into the server by hand.

The pipeline uses a Git‑based workflow: feature branches, pull requests into main, and automated checks that must pass before code is deployed. Deployments are reproducible, versioned via Docker tags, and can be rolled back using previous images.

Pipeline Design

How the CI/CD flow is structured

High‑level idea:

On every push or pull request to the main branch, GitHub Actions (or Jenkins) spins up a runner, installs dependencies, runs tests, builds a Docker image, pushes it to Docker Hub, and finally connects to the target server to pull the new image and restart the container using a simple deployment script.

Stages inside the pipeline
1. Trigger Pipeline triggers on push and pull_request events targeting the main branch. Manual “workflow_dispatch” is also enabled for on‑demand deploys.
2. Checkout & Setup The runner checks out the repository, sets up the correct runtime (Node/Python/etc.) and restores cached dependencies to speed up builds.
3. Tests & Lint Runs unit tests and linters. If any test fails, the pipeline stops and the deployment does not continue.
4. Docker Build Builds a Docker image for the app using the Dockerfile in the repo, tags it with the commit SHA and “latest” for easy rollback.
5. Push to Registry Logs into Docker Hub (or another registry) using stored secrets and pushes the newly built image so the server can pull it.
6. Deploy to Server Uses SSH or GitHub Actions self‑hosted runner to connect to the target VM, pulls the new image, and restarts the container using a small deployment script (docker‑compose or plain docker).

Learnings

Skills gained from this pipeline

Key technical takeaways
  • Understanding how CI and CD are separated but connected through artifacts (Docker images).
  • Writing reusable workflows / Jenkins pipelines with multiple stages and conditions.
  • Managing secrets and environment variables securely in the CI/CD system.
  • Deploying containerized apps on a Linux host and handling zero/minimal downtime restarts.
Next improvements
  • Add staging environment with approval before production deploys.
  • Integrate automated integration tests / smoke tests after deployment.
  • Extend the pipeline to deploy to Kubernetes (EKS / AKS) instead of a single VM.
